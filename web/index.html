Comparativa Fundamental de Control de Flujo CI-0117 Conceptos Clave
🔐 Mutex (Cerrojo) Exclusión Mutua
🔑 Analogía: La llave de un baño individual. Solo una persona puede tenerla; quien entra cierra con seguro y al salir DEBE devolver la llave.
  • Dueño: Sí (Ownership estricto). Solo el hilo que hace lock() puede hacer unlock().
  • Valores: Binario (0 o 1).
  • Uso clave: Proteger secciones críticas pequeñas donde se modifican variables o estructuras compartidas.
  • C / POSIX: pthread_mutex_lock(&m)
🚦 Semáforo Contador Señalización & Capacidad
🎫 Analogía: Estacionamiento con N espacios y tiquetes. Si hay tiquetes disponibles pasas; si llega a 0, esperas.
  • Dueño: NO tiene dueño. Un hilo productor puede hacer post() para despertar a un consumidor en wait().
  • Valores: Entero no negativo (0 a N).
  • Uso clave: Notificación entre hilos y control de cupo (Buffer Acotado, Rotonda).
  • C / POSIX: sem_wait(&s) / sem_post(&s)
🛑 Barrera de Fase Punto de Encuentro
👥 Analogía: Punto de reunión de un tour guiado. Nadie avanza a la siguiente atracción hasta que los N turistas lleguen.
  • Propósito: Forzar a N hilos a esperar hasta que todos hayan concluido la fase de cálculo actual.
  • Valores: Contador decreciente hasta 0.
  • Uso clave: Algoritmos numéricos iterativos (Difusión de calor 2D, simulación de partículas).
  • C / POSIX: pthread_barrier_wait(&b)
⚡ Atomics (C11) Lock-Free Hardware
⚙️ Analogía: Torniquete mecánico de metro: avanza con un clic a nivel hardware sin necesidad de poner candados.
  • Propósito: Modificar enteros o banderas en memoria mediante instrucciones atómicas del CPU (Fetch-and-Add).
  • Ventaja: 0 costo de llamadas al sistema operativo ni cambios de contexto de hilos.
  • Uso clave: Contadores de métricas de alto rendimiento y banderas de parada.
  • C11 Standard: atomic_fetch_add(&val, 1)

🔒 Condiciones de Coffman

CI-0117 Concurrente

Las 4 condiciones que deben cumplirse simultáneamente para que ocurra un interbloqueo (deadlock):

  • 1. Exclusión Mutua: Un recurso solo puede ser usado por un hilo a la vez.
  • 2. Retención y Espera (Hold & Wait): Hilos retienen recursos mientras solicitan nuevos.
  • 3. No Apropiación (No Preemption): Ningún recurso puede ser quitado por la fuerza.
  • 4. Espera Circular (Circular Wait): Cadena cerrada donde $H_1$ espera a $H_2$, y $H_2$ espera a $H_1$.
// Prevención en C: Jerarquía de recursos de Dijkstra sem_t entry_permit; // ¡Rompe matemáticamente la espera circular!

🌐 Ciclo de Vida Sockets BSD

CI-0123 Redes

Máquina de estados estándar para servidores y clientes TCP en sistemas POSIX / Linux:

Servidor: socket() -> bind() -> listen() -> accept() -> recv/send() -> close() Cliente: socket() -> connect() -> send/recv() -> close()

En servidores concurrentes con Thread Pool, accept() entrega el file descriptor resultante a una cola protegida por semáforos.
